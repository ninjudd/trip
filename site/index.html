trip

Persistent terminal sessions.

trip is a tiny daemon that keeps your terminal sessions alive when you close a window. Your terminal becomes a lightweight client: close it to detach, open a new one to pick up where you left off. Think tmux, but radically simpler — no panes, no splits, no keybindings to memorize.

$ curl -fsSL https://trip.here/install.sh | bash

Builds the newest release from source into ~/.local, without sudo. Needs Rust's cargo, which rustup installs. Runs on macOS and Linux.

Close the window. Keep the session.

Run trip enter in a project and press Enter. The chooser starts on that workspace's session, and creates it if it doesn't exist yet. Start a build, an editor, or an agent, then close the tab. Later, open a new one, run trip enter in the same project, and press Enter again.

~/acme/webapp $ trip enter
sessions:  ↑/↓ + enter · 0-9 · q cancels
> 0) acme/webapp        (new session)
  1) notes        nvim

# enter creates the session and attaches
~/acme/webapp $ cargo test
   Compiling webapp v0.4.1
     Running unittests src/lib.rs

# close the window mid-run, then open a new one
~ $ cd acme/webapp
~/acme/webapp $ trip enter
sessions:  ↑/↓ + enter · 0-9 · q cancels
  0) acme/webapp.1         (new session)
> 1) acme/webapp    cargo
  2) notes          nvim

# enter reattaches, and trip redraws the session's screen
~/acme/webapp $ cargo test
   Compiling webapp v0.4.1
     Running unittests src/lib.rs
test result: ok. 214 passed; 0 failed; finished in 48.20s
~/acme/webapp $ ▍

Why trip

  • Sessions survive window closes. The daemon owns each session's terminal, so closing a tab, quitting your terminal app, or switching to a different one leaves the processes inside running.
  • Reattaching shows a clean screen. The daemon keeps a virtual terminal for every session and redraws its current screen when you attach, rather than replaying raw scrollback.
  • One key to switch. Press Ctrl-\ to open the session chooser and move this terminal to another session. Press it again to detach.
  • Sessions you can read from outside. trip screen shows a session's screen, trip log shows what happened in it over time, and trip send types into it, all without attaching.
  • Built for agents. Run trip on inside Claude Code or Codex, and trip log shows structured turns and tool calls instead of escape sequences. trip wrap drives any command over a JSONL protocol.
  • Upgrades leave your sessions alone. trip upgrade installs the newest release without restarting the daemon, which moves to the new version when its last session ends.

trip isn't a multiplexer, a terminal emulator, or a tmux clone. Your terminal does the rendering, the windows, and the tabs; trip just keeps what runs in them alive.

Make every tab a trip session

Set your terminal to start trip enter in each new tab. Closing a tab then detaches it, and a new tab reattaches.

macOS Terminal
In Settings → Profiles → Shell, set Run command to ~/.local/bin/trip enter, and When the shell exits to Close if the shell exited cleanly.
iTerm2
In Settings → Profiles → General, set Command to a custom shell, ~/.local/bin/trip enter. In Session, set After a session ends to Close.

The README covers every command, the detach key, window titles, and how the daemon works.
